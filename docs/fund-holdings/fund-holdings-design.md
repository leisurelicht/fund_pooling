# 持仓管理系统 — 功能与页面设计

> 状态：设计稿（未实现） | 更新：2026-11-25（修订 32）
>
> 本文只记录思路与设计，不贴代码。架构与口径见同名 `-arch-design` 文档。

---

## 一、目标与边界

做一本**自用的资产账本**（基金为主，预留股票扩展）。

用户使用顺序：A. 扫一眼总资产 → B. 翻看持仓 → C. 记一笔交易 → D. 看分析曲线。

**做**：记账、持仓总览、收益口径、定投计划；分析图表为二期。

**不做**：行情 K 线、下单交易、社交分享。

---

## 二、布局与导航

桌面端**顶部导航 + 宽内容区**。一级入口横向排开，内容区不再被侧栏挤占，9 列持仓表可以完整展开；
代价是顶部占掉约一行高度，用吸顶（滚动时固定在顶部）换回可用性。

```
┌──────────────────────────────────────────────────────────────────┐
│ [Logo] 资产账本   总览  交易  定投  分析  设置          [用户 ▼] │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  （内容区，最大宽度居中；表格可完整展开）                          │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘
```

- 导航项：图标 + 文字，当前页用**主色文字 + 底部 2px 主色下划线**，不整块填色
- 右侧用户区：头像 + 用户名，点开只有「退出登录」——设置已经是一级导航，菜单里不再重复
- 顶栏吸顶：滚动持仓表时导航始终可见；顶栏自身不参与横向滚动
- 内容区最大宽度居中，两侧留白；窄屏时收到最小留白
- 移动端不做两套导航：顶栏保留 Logo 与用户，五个入口沉到底部标签栏（图标 + 文字）

五个入口、四个页面，总览吞掉持仓（A 和 B 是连续动作），资产详情为下钻页。

| 导航 | 路由            | 回答的问题                           |
| ---- | --------------- | ------------------------------------ |
| 总览 | `/`             | 有多少钱、赚了多少、每只资产什么情况 |
| 交易 | `/transactions` | 做过什么、钱去哪了                   |
| 定投 | `/sips`         | 计划还在跑吗                         |
| 分析 | `/analysis`     | 为什么赚亏、风险集中吗（二期）       |
| 设置 | `/settings`     | 渠道、数据源、数据导出、外观         |

**为什么改回顶部**：侧栏在 160px 时仍占掉一列宽度，而一级入口只有五个，横向排布更省空间；
持仓表是整站最需要宽度的页面，优先让给它。之前保留侧栏是为了「折叠后更宽」，实际折叠状态
很少有人长期使用，收益不如直接不放侧栏。

## 三、总览（含持仓）— `/`

```
┌─ 资产指标条 ────────────────────────────────────────────────────┐
│ 总资产         今日涨跌         累计收益        持仓成本  在途   持仓天数│
│ ¥13,005.54   +38.62 +0.30%   +264.34 +2.07%  ¥12,741   ¥2,000  487 天│
└──────────────────────────────────────────────────────────────────┘
        价格更新至 12-15 · 汇率更新至 12-15            上次刷新 13:38:12
┌─ 工具栏 ────────────────────────────────────────────────────────┐
│ [按资产] [按渠道]   [显示已清仓]      [列设置]        [+ 记一笔]   │
├─ 持仓表格 ──────────────────────────────────────────────────────┤
│ 资产          类型   渠道     场所  份额    成本价  价格     市值    收益│
│ 易方达蓝筹精选 混合  支付宝   场外  1,234  2.1800  2.3450  2,895  +205│
│ 中欧医疗健康   混合  天天基金 场外  5,600  1.1020  1.0890  6,098   -73│
│ 沪深300ETF    指数  券商     场内  1,000  3.8800  4.0120  4,012  +132│
│ ...（共 16 只）                                                  │
├─ 合计行（sticky 底部）──────────────────────────────────────────│
│ 合计 3 只          市值 ¥13,005     收益 +264.34   +2.07%        │
└──────────────────────────────────────────────────────────────────┘
```

示例数字是自洽的：三行市值相加等于合计，合计收益除以持仓成本等于显示的收益率；
指标条的总资产等于表格合计（在途另计，不并入市值）。

- 资产指标是**一条条带，不是六张卡片**：一行六个指标，用 1px 分隔线分栏，总资产字号最大；
  窄屏折成两行。六张独立卡片宽度难以对齐，容易显得零散
- 六个指标：总资产、今日涨跌、累计收益、持仓成本、在途金额、持仓天数
- 页面打开时自动获取数据，之后每 60 秒自动刷新；指标条下方显示「价格更新至 12-15 · 汇率更新至 12-15」
- 缺汇率时在指标条下方追加提示「2 只外币资产无法折算」，点击跳设置页
- 今日涨跌的公式以架构文档 §3.8 为唯一来源：`Δ(市值 + 在途) + 当日分红 − 当日净流入 − 当日转移费`，
  涨幅百分比的分母是昨日（市值 + 在途）
- 持仓天数取所有当前持有资产中最早的初始持仓 / 买入日期，按自然日计算
- 默认 9 列：资产、类型、渠道、**场所**、份额、成本价、价格、市值、收益。其余进「列设置」
- 同一只基金可能同时有场外与场内两行，靠「场所」列区分；外币资产在价格列后标注币种
- 列设置以弹出面板触发：每列一个开关，默认 9 列开、其余（币种、占比、持有天数、已实现收益、
  累计手续费、收益率）关闭。开/关即时生效。拖拽调整列顺序，顺序存 localStorage 记住
- 移动端不提供拖拽：列设置面板只保留开关，顺序固定；理由是手机上拖拽热区太小，误操作多于收益
- 表头 sticky + 合计行 sticky bottom，中间滚动
- 默认按市值从大到小排序；点击任一列可切换排序，升序 / 降序轮换
- 「按资产」视图合并同一资产的多渠道持仓；「按渠道」视图按渠道分组，
  每组显示该渠道下的资产行 + 小计行，渠道列自动隐藏
- 工具栏提供「显示已清仓」开关，默认关闭；开启后列出 0 份额的行并淡化显示，**不计入合计**
- 合计行的「只数」只统计有份额的行；存在缺价或缺汇率的行时，合计行旁标注「N 行缺价未计入」
- 「记一笔」浮层挂 App 层，全域可触发
- 行点击进入资产详情 `/assets/{code}`

## 四、交易 — `/transactions`

日常交易由**定投计划自动生成**，手动录入只用于计划外的单笔和补漏。

### 4.1 待确认（核心交互）

```
┌─ 待确认（置顶，独立请求，不随下面翻页）──────────────────────────┐
│ 12-15  易方达蓝筹  定投买入  场外  ¥2,000  份额待定  [作废][确认]│
│ 12-15  中欧医疗    定投买入  场外  ¥1,000  份额待定  [作废][确认]│
│ 12-12  广发科技    手动买入  场外  ¥3,000  1,234 份  [修改][删除][确认]│
├─ 筛选 ─────────────────────────────────────────────────────────┤
│ [全部] [买入] [卖出] [分红]   [定投] [手动]   日期: [__]–[__]     │
├─ 流水 ─────────────────────────────────────────────────────────┤
│ 日期    资产        类型     场所 渠道   金额   份额  价格   状态   操作│
│ 12-01  易方达蓝筹  定投买入  场外 支付宝 2,000  922  2.1700 已确认 [撤销]│
│ 11-28  中欧医疗    手动卖出  场外 天天   500   459  1.0890 已确认 [撤销]│
│ 11-26  沪深300ETF  场内买入  场内 券商  4,000 1,000 4.0000 已确认 [撤销]│
│ ...                                                              │
│ 共 128 条                    ‹ 1 2 3 … 7 ›     每页 20 条        │
└──────────────────────────────────────────────────────────────────┘
```

翻页只影响流水区：待确认区是单独请求，不随页码变化；筛选条件写进 URL，刷新和返回都保留。

- 定投到期自动生成待确认交易，用户只需核对份额和净值后点「确认」
- 来源标记区分 `定投` / `手动`，流水表可筛
- 流水表带「场所」列：场内与场外的交易混在一张表里，只靠类型分不清是二级市场成交还是申购
- 操作列：**手动/场内的待确认**给 [修改] [删除] [确认]；**定投生成的待确认**只有 [作废] 与 [确认]，
  不能改也不能删——改日期或删掉都会让 (计划, 日期) 判重失效
- 已确认行只给 [撤销]（撤销后重录）
- 撤销转移时弹确认：「将同时撤销转出与转入两笔」；撤销后两笔都标为已撤销
- 已确认交易不可原地编辑，只能撤销后重录
- 点「确认」弹出确认弹窗，三个字段均可修改
- 流水表每页 20 条，底部页码控件；待确认区单独请求，不随流水翻页变化

```
┌─ 确认交易 ──────────────────────────────┐
│ 易方达蓝筹 · 支付宝  定投买入  ¥2,000     │
│                                           │
│ 份额    [922.47]        ← 可改            │
│ 净值    [2.1700]        ← 可改            │
│ 手续费  [¥3.00]         ← 可改            │
│                                           │
│ 平台确认份额: 922.47    ← 灰色参考值      │
│ 平台确认净值: 2.1680                      │
│                                           │
│         [取消]    [确认]                   │
└───────────────────────────────────────────┘
```

灰色参考值来自定投计划估算或用户上次填写，仅作提示，不限制修改。确认后交易进入流水表。

### 4.2 手动录入

全局「记一笔」浮层，类型决定表单字段：

**买入 / 卖出**：资产 → 场所（场内 / 场外）→ 渠道 → 金额/份额 → 价格 → 手续费。
搜索不到资产时可现场新建，需要填类型、币种与**标的市场**（CN / US，一期不支持港股）——
市场决定它的交易日历，QDII 不能默认按中国日历。
场外交易在 15:00 后提示按下一交易日价格；场内成交即确定，不进入待确认。
外币资产多一个「成交汇率」，默认取当日汇率、可改——它决定成本折成人民币的口径。

不同交易类型要填的字段不一样，不能共用一套表单：

| 类型 | 需要填 |
|---|---|
| 买入 / 卖出 | 金额与份额二选一（另一个自动算）、价格、手续费；**场外可留空份额与价格，确认时再补** |
| 现金分红 | 只需金额 |
| 红利再投 | 金额、份额、价格 |
| 份额调整 | 份额增量（可为负），不需要金额与价格 |

**转移**（平台间迁移、场外转场内）：资产 → 转出渠道与场所 → 转入渠道与场所 → 份额 → 日期。
金额是「结转成本」，由系统按摊薄单价带出、**不可编辑**；提交后一次生成转出与转入两笔。
转托管费可填，计入现金流出但不进成本。撤销任意一侧会连带撤销另一侧。

转移表单与买卖不同，字段如下：

```
┌─ 记一笔 · 转移 ─────────────────────────────────────────┐
│ 资产     [005827 易方达蓝筹精选 ▼]                       │
│ 转出     [支付宝 ▼]  场所 [场外 ▼]                       │
│ 转入     [券商-华泰 ▼]  场所 [场内 ▼]                    │
│ 份额     [500.00]                                       │
│ 结转成本 ¥1,082.50   ← 系统按摊薄单价算出，不可编辑       │
│ 日期     [2026-12-15]                                   │
│ 转托管费 [¥0.00]      ← 可选，计入现金流出               │
│                                                         │
│                      [取消]   [确认转移]                 │
└─────────────────────────────────────────────────────────┘
```

转出与转入必须是两个不同的持仓行；同一行转给自己会被拒绝。

**初始持仓**（首次使用时录入现有持仓）：

```
┌─ 记一笔 ──────────────────────────────────────────┐
│                                                    │
│ 类型   [初始持仓 ▼]                                 │
│       ──────────────────────────────                │
│ 资产   [000001 易方达蓝筹精选 ▼]                     │
│ 场所   [场外 ▼]                                    │
│ 渠道   [支付宝 ▼]                                   │
│ 日期   [2025-01-01]           ← 从哪天开始算         │
│ 份额   [1,234.56]                                   │
│ 成本   [2,690.00]            ← 累计投入（原币）      │
│ 汇率   [1.0000]              ← 仅外币显示，默认当日  │
│ 已实现 [¥0.00]               ← 可空，历史已落袋收益  │
│                                                    │
│              [记一笔]                               │
└────────────────────────────────────────────────────┘
```

和买入的区别：不需要填价格（历史价格由同步任务补齐），成本语义为累计投入而非本次金额，
金额符号跟随资产币种（人民币显示 ¥、美元显示 $），多了「成交汇率」（仅外币显示，默认取当日汇率）
与「已实现收益」字段（人民币口径）。每只资产 × 渠道 × 场所只允许一条未撤销的初始持仓，撤销后可重录。

## 五、定投 — `/sips`

定投是**交易录入的主要来源**。设好计划后，每次扣款日自动生成待确认交易，用户只需确认
份额和净值后点「确认」即可。整个月都不用打开支付宝看明细。

```
┌─ 定投计划 ──────────────────────────────────────────────────────┐
│ ┌─────────────────────────────┐ ┌─────────────────────────────┐ │
│ │ 易方达蓝筹 · 支付宝          │ │ 中欧医疗 · 天天基金          │ │
│ │ 每期 ¥2,000 · 每日           │ │ 每期 ¥1,000 · 每月 12 日     │ │
│ │ 下次 12-16 · 累计 ¥24,000    │ │ 下次 12-12 · 累计 ¥8,000     │ │
│ │ ● 进行中                     │ │ ● 进行中         顺延至 12-14│ │
│ │ [暂停] [修改] [结束]          │ │ [暂停] [修改] [结束]         │ │
│ └─────────────────────────────┘ └─────────────────────────────┘ │
│ ┌─────────────────────────────┐                                 │
│ │ 广发科技 · 天天基金          │   ⚠ 2 个计划有到期未确认的交易   │
│ │ 每期 ¥500 · 每周一           │                                 │
│ │ 下次 12-21 · 累计 ¥6,500     │                                 │
│ │ ● 已暂停                     │                                 │
│ │ [恢复] [修改] [结束]          │                                 │
│ └─────────────────────────────┘                                 │
│                                              [+ 新建定投计划]    │
└──────────────────────────────────────────────────────────────────┘
```

卡片固定四行：基金与渠道、每期金额与周期、下次扣款与累计已投、状态与操作。每日定投不显示
「顺延」；固定日期型在右侧标注本期处理结果；到期未确认的计划在列表顶部统一提示。

扣款日自动生成待确认交易。非交易日的处理按每个计划的策略：

| 策略 | 行为 |
|---|---|
| 顺延（默认） | 顺延到下一个「中国 + 标的市场」都开市的交易日扣款，该期算已执行；下一期仍按原周期 |
| 跳过 | 本期不生成、不占期数，下期仍按原周期 |

每日定投按**交易日**排期（周末与节假日没有记录），不存在顺延问题。顺延如果跨过下一期的原定
日期（比如春节整周休市），这一期丢弃并提示「本期未执行」。

到期未确认的计划在列表顶部提示。累计已投金额每次确认后自动更新。

新建/编辑计划用浮层，字段如下：

| 字段 | 说明 |
|---|---|
| 资产 / 渠道 | 搜索资产；渠道默认上次使用 |
| 每期金额 | 资产币种 |
| 周期 | 每日 / 每周 / 双周 / 每月 |
| 扣款日 | 每周、双周选周几；每月选 1–28 日；**每日不显示** |
| 遇非交易日 | 顺延（默认）/ 跳过；**每日不显示**——它的周期就是交易日集合 |
| 起始日 | 首个扣款日不早于这一天 |
| 结束条件 | 不限 / 按次数 / 到某日 |

定投生成的交易固定为场外申购（场内没有自动扣款通道），因此计划本身不选场所。界面不按场所
置灰——「场内/场外」记在交易上，不在资产上，同一只 LOF 既可以场内买也可以场外申购。

**扣款日要求「中国交易日 且 标的市场交易日」**：纳指、标普这类 QDII 在美股休市日没有净值、
基金公司通常暂停申购，只按中国日历判断会在感恩节、圣诞、独立日生成无法确认的交易。
计划卡片上标注本期状态，按策略区分：「顺延至 12-01」「本期跳过（skip）」「本期未执行（顺延跨周期）」。

交易日历超出覆盖年份时，页面提示「交易日历需升级，当前按工作日判断」。

## 七、资产详情 — `/assets/{code}`

下钻页，不占一级导航。从持仓表格行点击进入。

```
┌ ← 返回  易方达蓝筹精选 ─────────────────────────────────────────┐

│ 券商·场内   500       2.1500  1,175   +100    +9.30%    +9.40%   │
│ 合计        1,734  持仓成本 ¥3,772  市值 ¥4,070  收益 +305       │
├─ 价格走势 ──────────────────────────────────────────────────────┤
│ [近1月] [近1年] [全部]     [净值] [收盘价]      折溢价 +0.2%     │
│  ╱╲                                                              │
│ ╱  ╲___                                                          │
│           ╲___╱                                                   │
├─ 最近价格 ──────────────────────────────────────────────────────┤
│ 12-15   2.3450   自动                                            │
│ 12-12   2.3300   手工   [删除]                                   │
├─ 交易时间线 ────────────────────────────────────────────────────┤

│ ...                                                [查看全部 →]  │
└──────────────────────────────────────────────────────────────────┘
```

场外资产头部只显示净值，没有折溢价与「收盘价」切换。

页面左上角有返回按钮，回到来源页并保留原来的筛选与滚动位置（从持仓行、交易时间线进来的
都要能回去）。

多渠道持仓分行显示 + 合计行。行内「成本价」是原币摊薄单价（与同行的「价格」同币种），
合计行的「持仓成本」是人民币总额——两个数不是同一量纲，标签必须分开写。场外资产头部只显示「最新净值」；上市资产（is_listed）显示
「收盘价 · 净值 · 折溢价」，折溢价 = 收盘价 ÷ 净值 − 1，缺净值时显示「—」。
价格走势只画该资产：场外资产只有净值一条线；上市资产可切换净值与收盘价。
交易时间线只显示该资产的最近交易，可点击跳转交易页并预填该资产的筛选条件。

价格区块里有「填写价格」入口（不限于价格缺失时，也用于纠正错误的自动价）：选日期、填价格
（场内填收盘价、场外填净值），保存后立即重算。下方是最近价格列表，每行显示来源：自动 /
**手工**；手工行可删除，删除后同步任务会把它当缺失重新拉取。

数据源恢复同步时不覆盖手工填写的行；手工值写错一次也不会永久卡住——删掉即可回到自动。

持仓摘要同时给三种收益率并标注口径：持仓收益率、累计收益率、年化收益率——前两个看当前
仓位与总投入，年化看时间价值，单给一个在定投场景下一定会误导。

累计收益率**不含**初始持仓录入之前的历史已实现收益（那部分没有对应的投入成本可做分母），
界面上用小字标注；累计收益金额本身仍包含它。

## 八、设置 — `/settings`

四块内容按两列排布，窄屏折成一列；每一块都是独立卡片，标题在左上、操作在右上。

### 渠道管理

渠道列表，每行：名称、类型、是否默认、状态。操作：新建、设为默认、归档、取消归档、删除。
归档的渠道不出现在录入选项，但历史流水中的渠道名称保留不变。

**删除只对「没有任何引用」的渠道开放**：手工建错的、重复建的渠道可以删掉；一旦有交易
或定投计划挂在该渠道下，按钮换成「已使用」提示，只能归档。原因是有引用时删除要么让历史
流水变成悬空引用，要么被迫连带删除——两者都会破坏账本可回溯性。

删除默认渠道后，按「创建时间最早的非归档渠道」顺延默认。

### 数据源

| 项 | 说明 |
|---|---|
| 启用开关 | 关闭后系统完全离线，价格与汇率只接受手工录入 |
| 价格同步 | 显示「价格更新至 12-15」，失败时显示「同步失败（12-13）」 |
| 汇率同步 | 显示「汇率更新至 12-15」；从未同步过汇率时提示「外币资产无法折算」 |
| 手动同步 | 按钮触发，实时返回结果：价格成功 N 只 / 失败 M 只，汇率成功 / 失败 |
| 手工填汇率 | 选币种对与日期、填汇率；数据源恢复后不覆盖手工填写的行；手工值可删除回退 |

### 外观

跟随系统 / 浅色 / 深色三选一，独立于系统设置。绿涨红跌开关。

### 数据

| 项 | 说明 |
|---|---|
| 导出数据 | 全部交易流水导出为 CSV，含原币金额、成交汇率、场所——缺了这三列账本无法复原 |
| 重算快照 | 选起止日期重算；展示重算了哪些日期、跳过了哪些及原因。补录历史交易或手工补价后用 |
| 清空所有数据 | 二次确认 + 输入「确认删除」；清空交易、转移、定投、渠道、快照、设置，保留共享的资产字典与价格/汇率 |

清空确认框要明确列出范围与不可恢复，而不是一句「确定吗」：

```
┌─ 清空所有数据 ──────────────────────────────────────────┐
│ 将删除：128 条交易、3 个定投计划、4 个渠道、46 天快照     │
│ 保留：资产字典、价格与汇率（不含手工填写的行）            │
│                                                         │
│ 此操作不可恢复。请输入「确认删除」： [__________]        │
│                                                         │
│                          [取消]   [清空]（未输入时禁用） │
└─────────────────────────────────────────────────────────┘
```

### 提醒（占位）

说明文字：「定投扣款提醒等功能将在后续版本上线」，不提供可点击的假入口。

## 十、关键流程

**日常**：设好定投计划后不需任何操作。扣款日系统自动生成待确认交易 → 净值公布后点
「确认」补份额和净值 → 持仓自动更新。

**新增一只基金**：在支付宝买一笔 → 来系统新增该基金的定投计划 → 首次扣款后系统自动
记录，之前的持仓通过「初始持仓」录入一次。

**月底核对**：翻平台账单核对总资产与持仓。对不上时，在交易页按日期筛出当月流水，
手工补录漏掉的交易（平台不提供导出，没有批量导入的捷径）。

**临时买卖**：通过全局「记一笔」浮层手动录入。

## 十一、视觉规范

**整体风格：现代简约。** 少装饰、少分割线、用留白和字号层级区分信息密度。卡片为白底 +
1px 浅灰边框，阴影只在浮层出现。色彩克制——全站只有一套主色、一套涨跌色、一套中性灰阶。
不出现渐变按钮、不出现多余图标、不出现纯装饰元素。

> 本节是视觉令牌，色值与字号是设计参数而非实现细节；组件内部怎么写不在此约定。

### 11.1 颜色

| 角色 | 浅色 | 深色 |
|---|---|---|
| 页面底 | `#f8fafc` | `#0f172a` |
| 卡片 | `#ffffff` | `#152036` |
| 弱底（表头、悬停） | `#f1f5f9` | `#1e293b` |
| 边框 | `#e2e8f0` | `#26334d` |
| 主文字 | `#0f172a` | `#e2e8f0` |
| 正文 | `#475569` | `#cbd5e1` |
| 次要文字 | `#64748b` | `#94a3b8` |
| 主色 | `#2563eb` | `#3b82f6` |
| 主色浅底 | `#eff6ff` | 蓝 16% 透明 |
| 涨 | `#dc2626` | `#f87171` |

深色跟随系统；涨跌色提供「绿涨红跌」开关，切换后两色互换。成功与错误色只用于状态，
不复用为涨跌色——两者语义不同，混用会让「同步成功」看起来像「上涨」。

### 11.2 字体与数字

| 用途 | 字号 | 字重 |
|---|---|---|
| 页面标题 | 24 | 600 |
| 卡片/区块标题 | 15 | 600 |
| 指标条主数字 | 34 | 650 |
| 指标条次数字 | 19–21 | 550–600 |
| 表格与正文 | 13–14 | 400–500 |
| 表头、说明、时间 | 11.5–12.5 | 400–500 |

- 字体族：`Inter`、`PingFang SC`、系统无衬线；等宽字体只用于代码块
- 所有数字用等宽数字（tabular-nums），右对齐；金额千分位两位、份额最多四位、价格四位
- 涨跌用颜色 + 正负号 + 箭头三重编码，不只靠颜色

| 项 | 约定 |
|---|---|
| 间距 | 4 的倍数；页面左右留白 32–40，卡片内边距 14–20 |
| 圆角 | 卡片 12–14；按钮与输入 7–10；胶囊 999 |
| 描边 | 卡片 1px 边框；分割线只用 1px 浅边框，不用阴影代替 |
| 阴影 | 只有浮层与折叠按钮有，平时不出现 |

### 11.4 组件规格

| 组件 | 规格 |
|---|---|

## 十二、空状态

| 页面 | 状态 | 展示 |
|---|---|---|
| 总览 | 无任何资产 | 「还没有持仓。先创建渠道，再录入初始持仓。」+ 创建渠道 / 记一笔 按钮 |
| 持仓表格 | 有渠道但无交易 | 不显示空表头，替换为引导文案「还没有交易记录，记第一笔吧」 |
| 持仓行 | 某资产无净值 | 价格与市值列显示「—」，悬浮提示「暂无净值，点击填写」 |
| 持仓行 | 外币资产缺汇率 | 市值列显示「—」，悬浮提示「缺少汇率，去设置页同步」 |
| 交易页 | 无任何流水 | 「暂无交易记录」+ 记一笔 入口 |
| 定投页 | 无任何计划 | 「暂无定投计划」+ 新建计划 按钮 |
| 定投页 | 计划全部结束 | 保留已结束卡片并置灰，顶部提示「没有进行中的计划」 |
| 分析页 | 二期未实现 | 「分析功能将在后续版本上线」 |

所有空状态引导可关闭，关闭后显示纯空态。净值缺失不作为空状态——表格行保留，只是价格
和市值列留空，不把资产从持仓里移除。

## 十三、异常状态

| 场景 | UI 处理 |
|---|---|
| 价格同步失败 | 总览资产卡片旁显示黄色提示「价格更新至 12-13，3 只资产未更新」。点击跳转设置页手动同步 |
| 某资产完全没有净值 | 持仓行价格、市值显示「—」。走势图该资产不参与绘图。交易时间线正常显示 |
| 外币资产缺汇率 | 折算后市值显示「—」，不做 1:1 顶替；总览提示「N 只外币资产缺少汇率」 |
| 场内资产只有收盘价、缺净值 | 市值正常（用收盘价），折溢价显示「—」 |
| 定投扣款日已到但净值未出 | 待确认交易正常生成，净值栏显示「待公布」，不阻塞用户确认份额 |
| 定投扣款日遇休市（顺延） | 卡片显示「顺延至 X」；顺延跨过下一期原定日期时显示「本期未执行」 |
| 定投扣款日遇休市（跳过） | 卡片显示「本期跳过」；不计入期数，也不提示补录 |
| 网络断开 | 顶部持续提示条「无法连接服务器」，不阻塞已加载页面的浏览 |
