# 持仓管理系统 — 功能与页面设计

> 状态：设计稿（未实现） | 更新：2026-11-25（修订 18）
>
> 本文只记录思路与设计，不贴代码。架构与口径见同名 `-arch-design` 文档。

---

## 一、目标与边界

做一本**自用的资产账本**（基金为主，预留股票扩展）。

用户使用顺序：A. 扫一眼总资产 → B. 翻看持仓 → C. 记一笔交易 → D. 看分析曲线。

**做**：记账、持仓总览、收益口径、定投计划、分析图表。

**不做**：行情 K 线、下单交易、社交分享。

---

## 二、布局与导航

桌面端**左侧导航 + 宽内容区**。顶栏占横向空间、对 8 列以上的持仓表不利。

侧栏从上到下：**Logo + 名称** → **五个导航项**（当前页高亮）→ **底部用户区**（头像 + 用户名）。

**用户菜单只放「退出登录」**：设置已经是侧栏的一级导航，菜单里再放一次会造成两个「设置」。
用户菜单是账号级操作（退出、切换账号），不承载导航。

**侧栏可折叠**：折叠后只保留图标（Logo、导航图标、头像），宽度收窄，内容区随之左移；
折叠按钮浮在侧栏右边缘，收起时悬停图标显示文字提示。折叠状态存本地，下次打开保持一致。
桌面端用户需要横向空间看持仓表时折叠，移动端不提供折叠（底部标签栏）。

五个入口、四个页面，总览吞掉持仓（A 和 B 是连续动作），资产详情为下钻页。

```
┌──────┬──────────────────────────────────────────────────────────┐
│      │                                                          │
│ 总览 │  （主内容区）                                             │
│ 交易 │                                                          │
│ 定投 │                                                          │
│ 分析 │                                                          │
│ 设置 │                                                          │
│      │                                              [用户] ▼    │
└──────┴──────────────────────────────────────────────────────────┘
```

| 导航 | 路由            | 回答的问题                           |
| ---- | --------------- | ------------------------------------ |
| 总览 | `/`             | 有多少钱、赚了多少、每只资产什么情况 |
| 交易 | `/transactions` | 做过什么、钱去哪了                   |
| 定投 | `/sips`         | 计划还在跑吗                         |
| 分析 | `/analysis`     | 为什么赚亏、风险集中吗（二期）       |
| 设置 | `/settings`     | 渠道、价格源、数据、外观             |

## 三、总览（含持仓）— `/`

```
┌─ 资产指标条 ────────────────────────────────────────────────────┐
│ 总资产        今日涨跌        累计收益       持仓成本  在途  持仓天数│
│ ¥128,430.55  +320.44 +0.25% +12,310.20 +10.61%  ¥116,120 ¥2,000 487 天│
└──────────────────────────────────────────────────────────────────┘
               更新于 13:38:12
┌─ 工具栏 ────────────────────────────────────────────────────────┐
│ [按资产] [按渠道]           [列设置]                 [+ 记一笔]   │
├─ 持仓表格 ──────────────────────────────────────────────────────┤
│ 资产          类型   渠道     份额     成本价   价格     市值   收益│
│ 易方达蓝筹精选 基金  支付宝   1,234   2.1800  2.3450  2,895  +203│
│ 中欧医疗健康   基金  天天基金 5,600   1.1020  1.0890  6,098   -73│
│ ...                                                             │
├─ 合计行（sticky 底部）──────────────────────────────────────────│
│ 合计 16 只          市值 ¥128,430     收益 +12,310   +10.61%     │
└──────────────────────────────────────────────────────────────────┘
```

- 资产指标是**一条条带，不是六张卡片**：一行六个指标，用 1px 分隔线分栏，总资产字号最大；
  窄屏折成两行。六张独立卡片宽度难以对齐，容易显得零散
- 六个指标：总资产、今日涨跌、累计收益、持仓成本、在途金额、持仓天数
- 页面打开时自动获取数据，之后每 60 秒自动刷新；指标条下方显示「更新于 HH:MM:SS」
- 今日涨跌由每日快照差分得出（今日市值 − 昨日市值 − 今日净流入），涨幅百分比以此作分母
- 持仓天数取所有当前持有资产中最早的初始持仓 / 买入日期，按自然日计算
- 默认 8 列：资产、类型、渠道、份额、成本价、价格、市值、收益。其余进「列设置」
- 列设置以弹出面板触发：每列一个开关，默认 8 列开、其余（占比、持有天数、已实现收益、
  累计手续费、收益率）关闭。开/关即时生效。拖拽调整列顺序，顺序存 localStorage 记住
- 表头 sticky + 合计行 sticky bottom，中间滚动
- 默认按市值从大到小排序；点击任一列可切换排序，升序 / 降序轮换
- 「按资产」视图合并同一资产的多渠道持仓；「按渠道」视图按渠道分组，
  每组显示该渠道下的资产行 + 小计行，渠道列自动隐藏
- 「记一笔」浮层挂 App 层，全域可触发
- 行点击进入资产详情 `/assets/{code}`

## 四、交易 — `/transactions`

日常交易由**定投计划自动生成**，月底 CSV 导入用于核对纠错，手动录入仅用于计划外的单笔。

### 4.1 待确认（核心交互）

```
┌─ 待确认（置顶）──────────────────────────────────────────────────┐
│ ⚠ 12-15  易方达蓝筹  定投买入  ¥2,000  份额待定    [确认]       │
│ ⚠ 12-15  中欧医疗    定投买入  ¥1,000  份额待定    [确认]       │
│ ⚠ 12-12  广发科技    手动买入  ¥3,000  1,234 份    [确认]       │
├─ 筛选 ─────────────────────────────────────────────────────────┤
│ [全部] [买入] [卖出] [分红]  [导入CSV]  日期: [____] – [____]    │
├─ 流水 ─────────────────────────────────────────────────────────┤
│ 日期      资产        类型      渠道    金额    份额  价格   状态 │
│ 12-01   易方达蓝筹   定投买入   支付宝  2,000   922  2.1700 已确认│
│ 11-28   中欧医疗     手动卖出   天天基金  500   459  1.0890 已确认│
│ ...                                                    [分页]   │
└──────────────────────────────────────────────────────────────────┘
```

- 定投到期自动生成待确认交易，用户只需核对份额和净值后点「确认」
- 来源标记区分 `定投` / `手动` / `导入`，流水表可筛
- 已确认交易不可原地编辑，只能撤销后重录
- 点「确认」弹出确认弹窗，三个字段均可修改

```
┌─ 确认交易 ──────────────────────────────┐
│ 易方达蓝筹 · 支付宝  定投买入  ¥2,000     │
│                                           │
│ 份额    [922.47]        ← 可改            │
│ 净值    [2.1700]        ← 可改            │
│ 手续费  [¥3.00]         ← 可改            │
│                                           │
│ 平台确认份额: 922.47    ← 灰色参考值      │
│ 平台确认净值: 2.1680                      │
│                                           │
│         [取消]    [确认]                   │
└───────────────────────────────────────────┘
```

灰色参考值来自定投计划估算或用户上次填写，仅作提示，不限制修改。确认后交易进入流水表。

### 4.2 手动录入

全局「记一笔」浮层，类型决定表单字段：

**买入 / 卖出**：资产 → 渠道 → 金额/份额 → 价格 → 手续费。15:00 后提示按下一交易日
价格。

**初始持仓**（首次使用时录入现有持仓）：

```
┌─ 记一笔 ──────────────────────────────────────────┐
│                                                    │
│ 类型   [初始持仓 ▼]                                 │
│       ──────────────────────────────                │
│ 资产   [000001 易方达蓝筹精选 ▼]                     │
│ 渠道   [支付宝 ▼]                                   │
│ 日期   [2025-01-01]           ← 从哪天开始算         │
│ 份额   [1,234.56]                                   │
│ 成本   [¥2,690.00]           ← 累计投入总额          │
│ 已实现 [¥0.00]               ← 可空，历史已落袋收益  │
│                                                    │
│              [记一笔]                               │
└────────────────────────────────────────────────────┘
```

和买入的区别：不需要填价格（历史价格由同步任务补齐），成本语义为累计投入而非本次金额，
多了「已实现收益」字段。每只资产 × 渠道只允许一条初始持仓。

### 4.3 CSV 导入（纠错）

```
┌─ 导入交易记录 ──────────────────────────────────────────────────┐
│                                                                 │
│   [拖拽 CSV 文件到此处，或点击选择]                               │
│                                                                 │
│   支持：支付宝基金、天天基金交易记录                               │
├─ 比对结果 ──────────────────────────────────────────────────────┤
│   23 条交易：20 条匹配（已跳过）、2 条新增、1 条金额不一致         │
│                                                                 │
│   ✓ 12-15  易方达蓝筹  买入  ¥2,000  ← 已自动记录，跳过          │
│   + 12-12  广发科技    买入  ¥3,000  ← 新增，将导入              │
│   ⚠ 12-01  中欧医疗    买入  ¥1,000  ← 系统 ¥980，CSV ¥1,000    │
│                                        [保留系统] [改用 CSV]     │
│                          [取消]                    [导入 2 条]   │
└──────────────────────────────────────────────────────────────────┘
```

每月从支付宝/天天基金导出 CSV，拖入后自动与已有交易比对。已自动记录的跳过，新增的补入，
金额/份额不一致的逐条标出，由用户选择保留系统记录还是覆盖为 CSV 值。未识别资产代码的
标红，手动关联后新增该资产并记住映射。

## 五、定投 — `/sips`

定投是**交易录入的主要来源**。设好计划后，每次扣款日自动生成待确认交易，用户只需确认
份额和净值后点「确认」即可。整个月都不用打开支付宝看明细。

```
┌─ 定投计划 ──────────────────────────────────────────────────────┐
│ ┌─────────────────────────┐  ┌─────────────────────────┐        │
│ │ 易方达蓝筹 · 支付宝      │  │ 中欧医疗 · 天天基金      │        │
│ │ 每期 ¥2,000  每月 15 日  │  │ 每期 ¥1,000  每周一     │        │
│ │ 下次 12-15  累计 ¥24,000 │  │ 下次 12-01  累计 ¥8,000 │        │
│ │ ● 进行中                 │  │ ● 进行中                │        │
│ │ [暂停] [修改] [结束]      │  │ [暂停] [修改] [结束]     │        │
│ └─────────────────────────┘  └─────────────────────────┘        │
│                                              [+ 新建定投计划]    │
└──────────────────────────────────────────────────────────────────┘
```

扣款日自动生成待确认交易。扣款日落在非交易日 → 本期跳过、不顺延。到期未确认的计划在
列表顶部提示。累计已投金额每次确认后自动更新。

## 八、设置 — `/settings`

### 渠道管理

渠道列表，每行：名称、类型、是否默认、状态。操作：新建、设为默认、归档、取消归档、删除。
归档的渠道不出现在录入选项，但历史流水中的渠道名称保留不变。

**删除只对「没有任何交易引用」的渠道开放**：手工建错的、重复建的渠道可以删掉；
一旦有交易挂在该渠道下，按钮换成「已使用」提示，只能归档。原因是有交易时删除要么让
历史流水变成悬空引用，要么被迫连带删除流水——两者都会破坏账本可回溯性。

### 价格源

| 项 | 说明 |
|---|---|
| 启用开关 | 关闭后系统完全离线，价格只接受手工录入 |
| 最后同步时间 | 显示「价格更新至 12-15」，失败时显示「同步失败（12-13）」 |
| 手动同步 | 按钮触发，实时返回同步结果（成功 N 只 / 失败 M 只） |

### 外观

跟随系统 / 浅色 / 深色三选一，独立于系统设置。绿涨红跌开关。

### 数据

| 项 | 说明 |
|---|---|
| 导出数据 | 全部交易流水导出为 CSV，用于备份或迁移到其他工具 |
| 清空所有数据 | 二次确认 + 输入「确认删除」 |

**为什么设置页不放「导入」**：导入交易记录是「这个月买了什么」的对账动作，属于交易页的
工作流；设置页是低频配置页，重复入口会让用户怀疑是不是两套不同的导入。录制入口只保留
交易页一处。

### 提醒（占位）

说明文字：「定投扣款提醒等功能将在后续版本上线」，不提供可点击的假入口。

## 十、关键流程

**日常**：设好定投计划后不需任何操作。扣款日系统自动生成待确认交易 → 净值公布后点
「确认」补份额和净值 → 持仓自动更新。

**新增一只基金**：在支付宝买一笔 → 来系统新增该基金的定投计划 → 首次扣款后系统自动
记录，之前的持仓通过「初始持仓」一次性导入。

**月底核对**：从支付宝/天天基金导出 CSV → 拖入系统 → 与自动记录的交易比对。已自动
记录的跳过，漏掉的补入，不一致的标出。

**临时买卖**：通过全局「记一笔」浮层手动录入。

## 十一、视觉规范

**整体风格：现代简约。** 少装饰、少分割线、用留白和字号层级区分信息密度。卡片为白底 +
1px 浅灰边框，阴影只在悬浮时出现。色彩克制——全站只有一套主色（蓝）、一套涨跌色（红/绿）、
一套中性灰阶。不出现渐变按钮、不出现多余图标、不出现纯装饰元素。

色板参考 QDII Lens（qdiilens.com）：浅色背景近 `#f8fafc`、卡片纯白、边框 `#e2e8f0`、
正文灰阶偏冷（slate），主色蓝、涨红跌绿。状态用浅色胶囊标签（浅底 + 同色文字），
不用实心色块。数字统一等宽数字（tabular-nums），不使用等宽字体。

具体规则：

- **图标统一用单色线性 SVG**：同一视窗、同一描边粗细、随文字着色，不用 emoji 或彩色图标
- **红涨绿跌**，提供「绿涨红跌」开关
- 涨跌用颜色 + 正负号 + 箭头三重编码
- 图表系列色避开红绿语义，用中性色
- 深色模式跟随系统
- 大额数字千分位；空值显示「—」，不用 0 冒充

## 十二、空状态

| 页面 | 状态 | 展示 |
|---|---|---|
| 总览 | 无任何资产 | 「还没有持仓。先创建渠道，再录入初始持仓。」+ 创建渠道 / 记一笔 按钮 |
| 持仓表格 | 有渠道但无交易 | 不显示空表头，替换为引导文案「还没有交易记录，记第一笔吧」 |
| 持仓行 | 某资产无净值 | 价格与市值列显示「—」，悬浮提示「暂无净值，点击填写」 |
| 交易页 | 无任何流水 | 「暂无交易记录」+ 导入 CSV / 记一笔 入口 |
| 定投页 | 无任何计划 | 「暂无定投计划」+ 新建计划 按钮 |
| 分析页 | 二期未实现 | 「分析功能将在后续版本上线」 |

所有空状态引导可关闭，关闭后显示纯空态。净值缺失不作为空状态——表格行保留，只是价格
和市值列留空，不把资产从持仓里移除。

## 十三、异常状态

| 场景 | UI 处理 |
|---|---|
| 价格同步失败 | 总览资产卡片旁显示黄色提示「价格更新至 12-13，3 只资产未更新」。点击跳转设置页手动同步 |
| 某资产完全没有净值 | 持仓行价格、市值显示「—」。走势图该资产不参与绘图。交易时间线正常显示 |
| 定投扣款日已到但净值未出 | 待确认交易正常生成，净值栏显示「待公布」，不阻塞用户确认份额 |
| CSV 导入有冲突 | 逐条标出差异（系统记录 vs CSV 记录），用户逐条选择保留哪个。全部解决后才允许提交 |
| CSV 导入有未识别代码 | 标红，用户手动关联资产后记住映射。不关联的跳过不导入 |
| 网络断开 | 顶部持续提示条「无法连接服务器」，不阻塞已加载页面的浏览 |
