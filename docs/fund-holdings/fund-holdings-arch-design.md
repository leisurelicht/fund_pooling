# 持仓管理系统 — 架构设计

> 状态：设计稿（未实现） | 更新：2026-11-25（修订 3）
>
> 本文只记录思路与设计，不贴代码。

---

## 一、目标与边界

做一本**自用的资产账本**（基金 + 未来扩展至股票）：只录交易流水，持仓、成本、收益全部
自动得出。

**做**：记账、持仓、收益口径、净值/价格同步、定投计划与提醒。

**不做**：行情 K 线、下单交易、社交分享、多用户协作、货币基金（一期）。

---

## 二、架构

| 层 | 职责 |
|---|---|
| Vue SPA | 展示、录入交互、数字格式化，不参与收益计算 |
| DRF 接口 | 鉴权、参数校验、序列化、筛选分页 |
| 领域计算（纯函数） | 份额重放、摊薄成本、收益与收益率 |
| PostgreSQL | Asset、AssetPrice、Channel、Transaction、SIPPlan、DailySnapshot |

全部业务模型放在一个 app `apps/portfolio` 下。

| 模型 | 职责 | 带用户外键 |
|---|---|---|
| Asset | 资产代码、名称、类型 | 否 |
| AssetPrice | 每只资产每个自然日的价格（基金净值 / 股票收盘价） | 否 |
| Channel | 购买渠道（支付宝、天天基金、券商等） | 是 |
| Transaction | 一笔买卖/分红/初始持仓的事实记录 | 是 |
| SIPPlan | 定投意向（仅基金） | 是 |
| DailySnapshot | 用户每日资产定格 | 是 |

## 三、核心口径

### 3.1 交易流水是唯一事实来源

持仓不建表，份额和成本由已确认交易实时重放得出：

- 初始持仓 → 份额、成本直接作为起始游标值
- 买入 → 份额增，成本增（金额 − 手续费）
- 卖出 → 按当前摊薄单价结转成本，差额计入已实现收益
- 红利再投（基金）→ 份额增，成本不变
- 现金分红 → 份额与成本不变，计入已实现收益
- 金额恒为正，方向由类型表达

Transaction 类型统一为：`opening_balance`（初始持仓）、`buy`（买入/申购）、`sell`
（卖出/赎回）、`cash_dividend`（现金分红）、`reinvest_dividend`（红利再投，仅基金）、
`share_adjustment`（份额调整，仅基金）。

### 3.2 收益

| 口径 | 定义 |
|---|---|
| 持仓收益 | 市值 − 剩余成本 |
| 已实现收益 | 卖出结转收益 + 现金分红 |
| 累计收益 | 持仓收益 + 已实现收益 |
| 持仓收益率 | 持仓收益 / 剩余成本 |
| 累计收益率 | 累计收益 / 累计买入净额 |
| 年化收益率 | 按每笔现金流日期计算的 IRR |
| 当日收益 | 今日市值 − 昨日市值 − 当日净流入 |

三种收益率并存，界面标注所用口径。用摊薄成本法。

### 3.3 每日快照

每天结算时写一行，锁定当日市值、成本、收益、在途金额。

用途：①走势图不随净值回补漂移；②当日收益 = 今日市值 − 昨日快照市值 − 当日净流入，
依赖昨日快照；③总览页「今日涨跌」的涨幅百分比同样从此差分得出。已有日期的快照不自动
改写；历史修正需用户显式触发。

### 3.4 初始持仓

每只资产 × 每个渠道一条：填当前持有的总份额、累计成本、历史已实现收益。在重放时直接
作为起始游标值，价格不存（由同步任务补齐），此后按正常交易叠加。每只资产 × 渠道只允许
一条初始持仓。

## 四、接口

全部挂 `/api/`，除 health 外均需登录，按当前用户过滤。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/api/assets/` | 搜索 / 新建资产 |
| GET | `/api/assets/{code}/` | 资产详情与我的持仓摘要 |
| GET | `/api/assets/{code}/prices/` | 价格区间 |
| POST | `/api/assets/sync/` | 手动触发价格同步 |
| GET/POST | `/api/channels/` | 渠道列表 / 新建 |
| PATCH | `/api/channels/{id}/` | 改名、设为默认、归档 |
| GET/POST | `/api/transactions/` | 流水列表 / 记一笔 |
| PATCH | `/api/transactions/{id}/` | 修改待确认交易 |
| DELETE | `/api/transactions/{id}/` | 删除待确认交易 |
| POST | `/api/transactions/{id}/confirm/` | 转为已确认 |
| POST | `/api/transactions/{id}/void/` | 撤销 |
| GET | `/api/positions/` | 持仓（按资产 / 按渠道） |
| GET | `/api/summary/` | 总览头部数字与榜单 |
| GET | `/api/snapshots/` | 资产走势区间 |
| GET/POST | `/api/sip-plans/` | 定投计划列表 / 新建 |
| PATCH | `/api/sip-plans/{id}/` | 暂停、恢复、修改 |

## 五、关键流程

**定投自动生成（主流程）**：设好定投计划 → 扣款日系统根据计划参数自动生成待确认交易
（source=sip，金额已知、净值待填）→ 用户确认时补份额、净值、手续费 → 交易转为已确认
→ 持仓重放自动纳入。扣款日落在非交易日时本期跳过。

**CSV 导入比对（月度纠错）**：从支付宝/天天基金导出 CSV → 拖入系统 → 自动识别来源与
列映射 → 按（资产 + 类型 + 日期 + 金额 + 份额）与已有交易逐条比对 → 已自动记录的跳过、
新增的补入、金额/份额不一致的逐条标出由用户选择保留系统记录还是覆盖为 CSV 值 →
未识别资产代码的手动关联后记住映射 → 确认后整批写入，任何一条失败则整批回滚。

**手动录入（补充）**：通过「记一笔」接口提交交易（类型 buy/sell/opening_balance 等）→
提交后默认 status=pending → 用户确认时补份额和净值 → 转为 confirmed。初始持仓类型
不要求价格，份额和成本直接作为重放起始游标值。

**首次使用**：登录 → 创建渠道 → 录入初始持仓（或从支付宝/天天基金导出 CSV 导入）→
同步历史价格 → 持仓出现。

**每日结算**：取有持仓的资产 → 逐只拉最新价格（幂等写入）→ 算当天快照（总市值、
剩余成本、持仓收益、已实现收益、在途金额、当日净流入、当日收益）→ 记录同步结果。

## 六、设计决策

| 决策 | 理由 |
|---|---|
| 交易流水是唯一事实来源，持仓实时派生 | 多一份状态就多一处不一致 |
| 渠道独立成表 | 「所有持仓」是多渠道之和 |
| 摊薄成本法 | 与国内平台口径一致 |
| 三种收益率并存并标注 | 单一口径必然误导 |
| 快照只做用户日聚合 | 资产级行数过高 |
| 历史快照不自动改写 | 静默修正破坏信任 |
| 撤销而非删除 | 保留审计痕迹 |
| 金额为正、方向由类型表达 | 避免四处判断符号 |
| 不引入 Celery/Redis | 一天一次同步，crontab 足够 |
| 前端不做口径计算 | 避免两处公式漂移 |
| Transaction 类型统一为 buy/sell | 未来加股票不需新增类型 |

## 七、边界

| 情况 | 处理 |
|---|---|
| 新资产无价格 | 显示「—」，不按成本冒充市值 |
| 价格接口失败 | 提示最后成功日期，不写脏数据 |
| 卖出份额超可用 | 拒绝，提示可用份额 |
| 定投扣款日非交易日 | 本期跳过，不顺延 |
| 重复初始持仓 | 拒绝，提示先撤销旧的 |
| 渠道下有交易时删除 | 拒绝，只允许归档 |
| 渠道无交易引用时删除 | 允许，二次确认；删除默认渠道后顺延到下一个可用渠道 |
| 跨用户访问 | 强制按用户过滤 |
| 货币基金 | 一期明确拒绝 |
| CSV 导入与系统记录不一致 | 逐条标出差异，用户选择保留系统记录或覆盖为 CSV 值 |
| 定投扣款日净值未出 | 待确认交易正常生成，净值字段留空，不阻塞用户后续确认 |
| CSV 导入含未识别资产代码 | 标红，用户手动关联资产后记住映射；未关联的跳过不导入 |

## 八、未来扩展

### 8.1 股票

设计已预留扩展空间：
- `Asset` 类型枚举预留 `stock`（A 股/港股/美股），新建时选类型即可
- `Transaction` 类型 `buy`/`sell`/`dividend` 直接对应股票买卖分红
- `AssetPrice` 的 `price_type` 区分收盘价（股票）和净值（基金）

需新增的能力：
- 货币字段（港股/美股需汇率换算后合并 CNY 合计）
- 交易时段感知（股票盘中价格 vs 基金日终净值）

### 8.2 其他

- 货币基金独立口径
- 定投提醒
- 基准对比、回撤、相关性
- OCR 截图记账
- 多币种
- 年度报告导出
